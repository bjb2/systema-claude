# Worked example: format-contract validation between routine steps

This routine is shipped **disabled** (`status: disabled`). It exists as a teaching artifact, not a feature you should run as-is. Read the body, copy the pattern when you write your own routines.

## What it does

Three steps:

1. **`count_tasks`** — runs a Python one-liner that counts files under `tasks/*.md` and prints JSON to stdout: `{"active_count": 42}`.
2. **`validate`** — parses that JSON and checks the shape. Asserts the structure (it's a dict), the required field exists (`active_count`), and the type is correct (int). If any check fails, the routine aborts here (`on_failure: abort`).
3. **`write_summary`** — writes a markdown report referring to the validated count. Only runs if step 2 passed.

The contract between step 1 and step 3 is **the JSON schema**, not a vague assumption that "the previous step will produce something useful." If the python in step 1 ever changes — renames the field, returns a string instead of an int, returns null on empty — step 2 catches it before step 3 silently writes garbage.

## Why this matters

systema-claude has no second user looking over your shoulder. When step 1 silently changes its output shape — because you edited it, because Python's `os.listdir` behavior changed, because the model that generated step 1 produced subtly different code on a re-run — step 2 is your only signal that the contract drifted.

A routine that passes prose between steps with no validation is a **register contract**: "the previous step will produce something useful, the next step will figure it out." That's how multi-step routines fail silently. A routine that validates shape at the boundary is a **format contract**: "the previous step will produce X-shaped data, and we'll fail loudly if it didn't."

When you write your own routines, ask: what step boundary needs a contract? Then write a tiny validator step there. Inline asserts work; full JSON schemas work; calling out to `examples/harness/validate-frontmatter.py` works. The form doesn't matter; the discipline does.

## Anti-patterns

Don't:

- Pass prose between agent steps and assume the next step will parse it. Agent output is a register contract by default; turn it into a format contract by giving the agent a schema and validating.
- Skip the validator because "the routine has worked for weeks" — that's exactly when contract drift starts compounding silently.
- Write the validator as a Tauri command or hidden Rust function — keep it inline so the routine is self-contained and inspectable in one read. The whole pattern is less useful if a reader has to grep three files to find the contract.

## Trying it

If you actually want to run this:

1. Flip `status: disabled` to `status: enabled` in the frontmatter.
2. The cron is `0 9 * * *` (9am daily, your local timezone). Adjust or set a manual trigger.
3. Watch `routines/runs/` after the next fire. Each run gets a JSON record of which steps passed and what they produced.

To intentionally trip the validator (and confirm the harness catches it), edit the python in `count_tasks` to print `{"count": 42}` instead of `{"active_count": 42}`. The next run should abort at `validate` with `missing active_count, got keys: ['count']`.

That fail-loud is the whole point.
